# `docs/retro/` —— 项目回顾

这个目录放**回顾性**文档：不是设计（那在 `design-v5.x.md`）、不是待办（那在 `TODO.md`），
而是**"我们做这件事的方式，哪里在失效"**。

## 为什么单开一个目录

本仓已经有 4 类文档，各管一件事，但**没有一类管"方法论本身"**：

| 文档 | 回答的问题 |
|---|---|
| `design-v5.x.md` | 系统**长什么样** |
| `TODO.md` | 还**欠**什么 |
| `CLAUDE.md` | 改代码前**必须知道**什么 |
| `changelogs/`（前端） | 这次**改了什么、为什么** |
| **`docs/retro/`（本目录）** | **我们做事的方式哪里在失效、怎么改** |

混进上面任何一个都会被稀释：放进 `TODO.md` 会变成"又一条债"，放进 `CLAUDE.md`
会变成"又一条约束" —— 而回顾的产物恰恰是**约束该放在哪一档**这件事本身。

## 写一份回顾的约定

1. **必须有证据**。每个结论后面能指到具体数字、提交、文件行 —— 没有证据的归因只是印象，
   而印象在回顾里最贵：它会变成一条错误的 Action。
2. **必须给判据**。每条 Action 要能被验证（"怎么知道改好了"），否则它和"应该"没有区别。
3. **必须承认失败**。执行者（包括 AI）的自述与事实不符的实例，是**最有价值的一手材料** ——
   因为它们暴露的是机制，不是个人。
