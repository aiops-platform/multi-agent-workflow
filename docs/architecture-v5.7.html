部署架构 · v5.7

AIOps 智能体平台

执行面按密钥边界切分：worker 容器持有全部凭据 （DeepSeek key / DB DSN / MCP 凭证 / git PAT），沙箱容器一个都不给， 只承接"写文件"与"跑测试"这两件会执行仓库代码的事。判据一句话—— 谁持有密钥，谁不执行不可信代码。

缺口 1工作区由 API 准备，却在 Worker Pod 被消费

RunService._create() 在 API 进程里 clone 到 {workspace_root}/{tenant}/{run}/repos/{service}，而消费方是 Worker Pod 里的 ws_read_file / ws_git。 本地单机同路径成立；集群形态下 API 跑在宿主、Worker 挂的是 emptyDir，两者不是同一个文件系统——Worker 会看不到仓库。

缺口 2沙箱与 worker 共享网络命名空间

sidecar 与 worker 同 Pod 同 netns，因此无法"只掐沙箱的出口、放行 worker"： NetworkPolicy 按 Pod 选，而 hostNetwork 下多数 CNI 根本不生效。 当前能兜底的只有沙箱没有任何凭据——它够不着需要认证的东西， 剩下能做的只是探测内网与外泄仓库内容。取舍见 docs/TODO.md §3。
